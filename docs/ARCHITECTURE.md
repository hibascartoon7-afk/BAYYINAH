# البنية التقنية

## المسار من الرسالة إلى النتيجة

```
رسالة المستخدم (نص أو صورة)
        │
        ▼
  قراءة الصورة (ocr.py)  ← إن كانت صورة
        │
        ▼
  توحيد النص (normalize.py)
  حذف التشكيل، توحيد الألف والتاء والياء، توحيد صيغ الصلاة على النبي ﷺ
        │
        ▼
  البحث في كل طبقة (engine.py)
  ├─ بحث بالمعنى: تضمينات + ChromaDB
  └─ بحث باللفظ: النصوص التي تحتوي كلمات السؤال نفسها
        │
        ▼
  بناء البطاقات: لكل نتيجة بطاقة مستقلة بمصدرها وأحكامها
  تصنيف: «نفس النص» أو «قريب في المعنى»
        │
        ▼
  القرار: found / related_only / fatwa / not_found
        │
        ▼
  الجملة التمهيدية (llm.py)
  نموذج لغوي بحمايات، أو جملة جاهزة
        │
        ▼
  الواجهة (app.py)
```

## الطبقات

| الطبقة | الملف | ترتيب العرض |
|---|---|---|
| `verified` | `data/verified_hadiths.json` | 1 (اختيارية، تُتخطّى إن غابت) |
| `sahihayn` | `data/hadith_database.json` | 2 |
| `rulings` | `data/rulings_database.json` | 3 |

وأي طبقة يغيب ملفها **تُتخطّى بهدوء** ولا تُسقط الأداة.

## البحث

| العنصر | القيمة | السبب |
|---|---|---|
| نموذج التضمين | `paraphrase-multilingual-MiniLM-L12-v2` | يدعم العربية، وخفيف للاستضافة المجانية |
| قاعدة المتجهات | ChromaDB، مسافة جيب التمام | |
| حدّ الامتناع | 0.35 لكل طبقة | ضُبط بالتجربة: أقرب نص لا علاقة له بالسؤال كان على مسافة 0.41 |
| شرط «نفس النص» | 80% من كلمات المستخدم موجودة في النص | يفرّق بين الحديث نفسه والقريب منه |
| المقاطع القصيرة | تُتجاهل في البحث بالمعنى إن قلّت عن 3 كلمات | تمنع الشظايا من تصدّر النتائج |

### لماذا بحث باللفظ مع البحث بالمعنى؟

ظهر بالتجربة أن «إنما الأعمال بالنيات» لم يظهر من صحيح البخاري في البحث بالمعنى، لأن متنه طويل فتبعد مسافته عن سؤال قصير.
فأُضيف بحث لفظي يجلب كل نص يحتوي كلمات السؤال نفسها، ثم تُحسب مسافته. فصار حديث البخاري رقم 1 يظهر أولًا.

## الفهرس والبصمة

يُبنى الفهرس **مرة واحدة**، ثم يُقرأ المحفوظ. ويُعاد بناؤه تلقائيًا إن تغيّر:

- ملف البيانات (ولو بقي عدد السجلات نفسه)،
- أو `normalize.py`، لأن الفهرس مبني على النص بعد توحيده.

وحمايتان من الفهرس الناقص:

1. **البصمة تُكتب بعد اكتمال الطبقة**، لا عند إنشائها.
2. **البصمة تُمحى قبل هدم الطبقة**، فلو انقطع البناء في منتصفه لا يبدو الفهرس جاهزًا وهو ناقص.

## شكل النتيجة

```json
{
  "decision": "found | related_only | fatwa | not_found",
  "message": "نص يُعرض للمستخدم",
  "input_type": "text | image",
  "extracted_text": "النص المستخرج من الصورة",
  "matches": [ "بطاقات النص نفسه" ],
  "related": [ "بطاقات القريب في المعنى — ليست جوابًا على السؤال" ]
}
```

### البطاقة

| الحقل | المعنى |
|---|---|
| `matn` | النص المعروض |
| `display_label` | «المتن» أو «نص الرواية كما في الكتاب» |
| `matn_trusted` / `matn_note` | هل النص متن خالص، وسبب التحفّظ إن لم يكن |
| `isnad` | الإسناد، يُعرض عند الطلب |
| `book` / `chapter` / `number` | المصدر وموضعه (الرقم يُخفى إن كان مشكوكًا فيه) |
| `source_type` | المصادر الأصلية أو كتب الأحكام |
| `diff` | فروق اللفظ بين ما كتبه المستخدم والنص |
| `agreement` | متفق / مختلف فيه / غير مصنّف / لا حكم في مصادرنا |
| `rulings` | أقوال العلماء الخاصة بهذا المدخل وحده |
| `note` | ملاحظة للمستخدم |

### الحكم داخل البطاقة

| الحقل | المعنى |
|---|---|
| `quote` | كلام المؤلف كما هو — **وهو ما يُعرض** |
| `scholar` / `book` / `location` | القائل وكتابه وموضعه |
| `quote_truncated` | كلام المؤلف مقتطع، فيُحال إلى المصدر |
| `quote_note` | في الكلام إحالات إلى حواشي المحقق |

## النموذج اللغوي

| العنصر | القيمة |
|---|---|
| المزوّد | Google Gemini |
| سلسلة النماذج | `gemini-3.8-flash` ← `gemini-3.5-flash-lite` ← `gemini-flash-lite-latest` |
| المهلة | 10 ثوانٍ لكل محاولة (أدنى ما تقبله Google)، ثم ينتقل إلى التالي |
| حدّ الكلمات | 1024، يتسع لتفكير النموذج؛ وطول الجواب يضبطه الفحص (400 حرف) |
| متى يُستعمل | حين يوجد النص بلفظه فقط |

والدالة `ask_model` وحدها تعرف أي نموذج يُستعمل، فتبديل المزوّد لا يمسّ بقية الكود.
وإن فشلت النماذج كلها، تعمل الأداة كاملة بجملة جاهزة: **فلا اعتماد حرج على خدمة خارجية**.
